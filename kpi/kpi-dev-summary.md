# 우프컴퍼니 공헌이익 KPI — 개발 현황 종합 정리

> 작성일: 2026-10-06 · 작성 목적: ChatGPT 등 외부 AI와 크로스체크하기 위한 전체 컨텍스트 공유 문서.
> 이 문서만 읽으면 프로젝트의 배경·설계·구현·미결사항을 모두 파악할 수 있도록 작성됨.

## 1. 프로젝트 개요

- **무엇**: ㈜우프컴퍼니(반려동물 커머스, 3인 법인)의 월별 **공헌이익(Contribution Margin) KPI + 보너스 정산 도구**
- **형태**: 서버 없이 동작하는 **단일 HTML 정적 페이지** (`kpi.html`, 1,173줄). 데이터는 브라우저 localStorage에 저장
- **왜 공헌이익인가**: 매출·영업이익이 아닌 "매출 − 변동비" 기준으로 보너스 판정. 회생 변제금 확보가 전제 조건이라 방어선(BEP) 개념이 핵심
- **개발 방식**: 본 앱(wooofpay, Node.js 정산관리 시스템)과 **격리된 폴더(`wooofpay/kpi/`)에서 독립 개발**. 완성 후 본 앱에 라우트/메뉴로 편입하고 role별 권한(owner/manager/operator)을 붙이는 계획
- **조직 컨텍스트**: 대표 이교영 + 직원 2인(김예빈·유재량). 2026년 초 회생 종결, 매년 회생변제금 납부 중

## 4. 화면 구조 (탭 3개)

### ① 월별 입력
- 월 선택 (2026년 1~12월) + "지난달 채널 구성 복사" + "⚡ clobe 자동값 적용" 버튼
- **유닛 2개**로 입력 테이블 분리:
  - **우프(입점)**: 타브랜드 입점매출 — 위탁·선매입 (기본 행: 입점브랜드 위탁 / 입점브랜드 선매입)
  - **PB 매출**: 자사 제작생산 제품 판매 (기본 행: 자사몰(PG) / 온라인 위탁(쿠팡·스토어 등) / 오프라인 위탁(백화점 등) / 공구 / 필바이츠 / 도톤 / 공감캣)
- 행(채널)은 자유 추가/삭제. 입력 필드 8개: **순매출, 수수료, 상품원가, 물류비, 프로모션비, 반품비, 기타변동비, 광고비**
- 픽키도기클럽 월매출 별도 입력칸 (보너스 풀 계산에만 사용)
- 자동값이 채워진 칸은 파란색 표시, 수동 수정한 칸은 보호(자동값으로 덮어쓰지 않음)
- **월 마감 체크리스트 6항목**: 공구 수수료 반영 / 물류비 누락 / 선지출 생산비 / 반품·환불비 / 정산 시차 메모 / 부가세·법인세 이중차감 금지
- 이번 달 결과 패널: 판정(1단/2단 통과 여부)·보너스 금액·목표매출 대비 실적

### ② 연간 현황
- 12개월 추이 테이블·차트 (CM1/CM2, 방어선, 판정)
- **분기 누적 정산 표**: 분기별 누적 CM2·누적 1단선·버퍼·2단선·스트레치·직원몫·월별 잠정지급 합·**트루업** 표시

### ③ 설정
- 구성원 3인 기본급·개인상한(capOverride), 직원 배분율, 월 비용 모드(예산표/안정월/연평균/직접입력), 회생 월변제액, 픽키 고정용역비, 판정 기준(CM1/CM2), 버퍼율, 기본보너스, 목표 CM율
- JSON 내보내기/가져오기 백업 (localStorage 유실 대비, "월 1회 백업" 안내문 포함)

## 5. 핵심 계산 로직 (kpi.html 구현 그대로)

### 5-1. 행/유닛 단위
```
정산매출(settle) = 순매출(net) − 수수료(fee)
CM1 = 정산매출 − 상품원가 − 물류비 − 프로모션비 − 반품비 − 기타변동비
CM2 = CM1 − 광고비
```

### 5-2. 월 판정 (2단 방어선)
```
회생부족분(rehabGap) = max(0, 월 회생변제액 − 픽키 고정용역비)   // 픽키 대행료가 회생재원
1단선(BEP)  = 월 비용(판관비) + 회생부족분
목표버퍼    = 월 비용 × 버퍼율(기본 30%)                        // 판관비 기준 (공헌이익 기준 아님!)
2단선       = 1단선 + 목표버퍼
판정기준(basis) = CM2 (설정으로 CM1 전환 가능)

1단 통과: basis ≥ 1단선 → 기본보너스 지급 (기본값 0원 = 미사용)
2단 통과: basis ≥ 2단선 → 초과분(basis − 2단선)을 스트레치로 배분
```

### 5-3. 보너스 배분
```
픽키 초과분 = max(0, 픽키월매출 × 10% − 픽키 고정용역비 200만)
스트레치 풀 = (2단선 초과분 × 직원배분율 50%) + (픽키 초과분 × 50%)
1인당 = 스트레치 풀 ÷ 3 (균등)
개인 상한 = capOverride > 0 ? capOverride : 기본급 × 배수(기본 100%)
  - 대표 이교영: capOverride 300만원 (기본급 80만이라 별도 상한)
지급액 = min(상한, 기본보너스 + 스트레치 1인분)
```

### 5-4. 분기 누적 정산 (적자달 상쇄)
```
분기 내 "입력이 있는 달"만 합산 (진행중 분기 왜곡 방지 — 미입력 달은 판관비도 제외)
누적 CM2, 누적 1단선, 누적 판관비 → 분기 2단선 = 누적1단선 + 누적판관비 × 30%
분기 스트레치 = max(0, 누적CM2 − 분기2단선), 직원풀 = × 50%
트루업 = 분기확정 직원풀 − 월별 잠정지급 합
  - 양수: 추가 지급 / 음수: 환수하지 않고 다음 분기 이월차감 (이월차감 자동화 UI는 미구현)
```

### 5-5. 목표매출 (동기부여용 참고값, 판정에 미사용)
```
목표매출 = 2단선 ÷ 목표CM율(기본 39%)
손익분기매출 = 1단선 ÷ 목표CM율
```
> 배경: 2026년 5월에 "매출은 목표를 넘었지만 CM율 19%로 미달"한 저마진 함정 사례가 있어, 매출 단독 판정은 위험하다고 결론. 판정은 반드시 공헌이익 기준.

## 7. clobe 자동채움 파이프라인

- **데이터 소스**: clobe MCP(api.clobe.ai) — 회계/은행거래 조회. 계정 이교영, 회사 4개(우프컴퍼니·베럴즈·엘브이더블유 MASTER, 픽키파크 MEMBER). 대상은 **우프컴퍼니 단일**
- **기준**: 은행 **실입금**(=정산매출) 기준 → 순매출 칸에 실입금을 넣고 수수료 칸은 비움 (혼동 주의)
- **흐름**: clobe 수집 → `autofill-raw.json` → `generate-autofill.py`(채널 매핑 테이블로 정규화) → `kpi-autofill.js` → kpi.html 버튼 클릭 시 적용
- **운영 모드**: 혼합(자동채움 + 수동보정). 수동 수정 칸은 자동값이 덮지 않음
- **알려진 데이터 이슈**:
  - clobe 채널 라벨링 비일관 (쿠팡이 4개 키로 분산되는 등 → 매핑 테이블로 병합)
  - 7월 clobe API 자체 집계가 행 합계와 34,830원 불일치 → 행 기준 값 채택
  - 현재 수집분은 2026년 1~7월. 8월 이후는 재수집 필요 (clobe 세션 재인증 필요할 수 있음)

## 9. 매출 분류 체계 (KPI 범위)

| 분류 | 내용 | KPI |
|---|---|---|
| 본업 (Pool A) | 자사몰, 입점브랜드(위탁/선매입), PB, 스마트스토어, 마켓, 공구 | ✅ 포함 |
