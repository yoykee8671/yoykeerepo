## 1. 픽키 정산서는 도톤과 구조가 다르다

도톤 것을 고쳐 쓸 수 없다. 시트 구성부터 다르다.

| | 도톤 | 픽키 |
|---|---|---|
| 1장 | 종합정산 (재고·실비·이익분배 한 장에) | **정산서** (판매종합 + 계산서발행 안내만) |
| 2장 | 채널별 판매데이터 정리 | **채널별 정산 합계** (신설) |
| 3장 | DB)입출고목록 | 채널별 판매데이터 정리 |
| 이후 | 채널 원본 | 채널 원본 (`DB)coupang` 등) |

### 픽키에만 있는 것 — 정산 주체 분리

`채널별 정산 합계`의 각 채널 블록에 **정산형태**(우프 / 픽키파크) 칸이 있고,
`정산서`가 그 둘을 나눠 합친다.

```
정산서 C11 = '채널별 정산 합계'!F26 + F34        (픽키파크 정산)
정산서 C12 = '채널별 정산 합계'!F6 + F22 + F42   (우프 정산)
```

- **우프 정산** — 우프가 수수료 계산서를 발행하고 정산금을 입금
- **픽키파크 정산** — 업체가 픽키파크로 직접 발행·입금 (우프는 전달만)

도톤에는 없는 개념이라 데이터 모델에 `settleBy`(이미 채널에 있음)를 정산서
집계까지 끌어와야 한다.

### 채널 블록의 칸

```
항목 · 정가합계 · 배송비합계 · 할인합계 · 최종결제합계 ·
공제(%) · 공제(원) · 정산합계 · 정산형태 · 비고
```

공제(%)는 숫자가 아닌 경우가 있다 — `품목별상이`(쿠팡), `네이버기준`.
배송비합계도 `쿠팡배송`·`자체배송`·`매장위탁판매` 같은 글자가 들어간다.
**숫자 칸에 글자가 들어갈 수 있다는 전제로 써야 한다.**

### 매출 없는 채널은 숨김

8월 기준 숨긴 행: 8~19, 28~31, 36~39 (betters_sm_st, wooof-B2B, 테일릿,
kurly, 파마스퀘어). 지우지 않고 **행 숨김**으로 둔다 — 채널 목록 자체는
유지해야 다음 달에 되살리기 쉽다.

## 3. 물류비 산정 변경 (`npb_3pl_cost.md`)

| 항목 | 기존 | 변경 |
|---|---|---|
| 3PL 택배 소형 | 2,650 | **2,500** (CJ대한통운) |
| 3PL 택배 중형이상 | — | **4,000** ← 양식과 불일치, 확인 필요 |
| 물류비(포장/부자재) | 1,300 | **800** |
| **합포비** | 없음 | **신설** |
| 본사출고 | 동일 | 3,000 + 500 |
| 용달/퀵 | 동일(별도청구) | 포장비만, 택배비 없음 |

### 합포비 계산

양식의 `합포비용 계산식` 시트가 근거다. **송장번호 단위**로:

```
합포추가수량 = max(0, 박스인입수량 − 1)
합포비       = 합포추가수량 × 100원
```

8월: 송장 95건 중 합포추가수량 합계 **325개** → 32,500원.

**박스단위 출고는 합포비 제외**(45g 100개입 / 180g 32개입). 중형이상으로
분류하고 박스 입수단위로 건수를 센다.

## 4. 나머지 요청

| | 내용 |
|---|---|
| 채널별 샘플양식 다운로드 | 업로드용 빈 양식을 채널마다 받을 수 있게. 받은 DB 원본의 열 구성을 기준으로 |
| 채널 설정 메모 | 채널마다 한 줄(길게). 평소엔 안 보이고 [수정] 눌러야 입력칸 활성 |
| 청구서 다운로드 일원화 | 워크시트 하단과 미리보기 두 곳이 같은 파일을 받아야 함 |
| 워크시트 채널별 [반영] | 채널 블록마다 저장 버튼 |
| 할인 칸 활성화 | 지금은 계산 결과라 입력 불가 — 직접 입력도 되게 |
| 채널별 끝자리 처리 | 올림/반올림/내림 선택 (거래관리에 이미 있는 방식) |
| 재고 입출고 파싱 오류 | 받은 원본으로 재현해서 고칠 것 |
| 실비 기준 저장 버튼 | 지금 고쳐도 저장이 안 됨 |

### ⚠️ 정산 확정된 달은 불변

실비 단가나 수수료율을 바꿔도 **이미 확정한 달의 금액이 달라지면 안 된다.**
지금은 기준값을 브랜드 설정에서 매번 읽어 계산하므로, 기준을 바꾸면 과거
정산서까지 소급해 달라진다.

→ 확정 시점의 기준을 그 정산에 **스냅샷으로 저장**하고, 확정된 달은 그
스냅샷으로만 계산해야 한다. 발주서가 발행자 정보를 스냅샷으로 들고 있는 것과
같은 방식.

## 5. 정가 / 기준가 / 할인 — 지금 동작

워크시트 칸의 뜻은 이렇다.

```
정가   = 소비자 정상가 (상품표 값)
기준가 = 그 채널에서 실제로 팔린 개당 단가 (할인·프로모션 반영 후)
할인   = 정가 − 기준가 (개당)   ← 계산 결과라 입력칸이 아니다
매출계 = 기준가 × 수량
```

할인이 입력칸이 아닌 이유는, 정가와 기준가가 있으면 할인은 자동으로 정해지기
때문이다. 다만 **할인을 먼저 알고 기준가를 모르는 경우**가 있어, 할인에
적으면 기준가가 역산되도록 바꾸는 편이 낫다(검수표는 이미 그렇게 동작한다).
