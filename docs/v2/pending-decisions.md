# 대표 확인 필요 (2026-11-16 야간 작업 중 모은 것)

대표가 자는 동안 '추천' 방식으로 먼저 진행했다. 아래는 확인받고 필요하면 고칠 것들.

## 채널톡(메신저) 연동
1. **무료 플랜은 Open API 를 쓸 수 없음**(채널톡 공식 플랜표: 무료+ = 개발 기능 '사용 불가', 체험판도 Open API 제외). 받아 둔 값은 키만 있고 비밀값(secret)이 없어 인증 실패(401).
   - 지금 한 것: 알림 문구를 ERP 안에 쌓고 [복사] 버튼으로 팀챗에 붙여 넣는 방식 + 키·비밀값이 생기면 바로 켤 수 있는 발송 기능(꺼 둠).
   - 정할 것: ① 지금처럼 복사·붙여넣기 ② 채널톡 Startup 이상으로 올려 자동 발송 ③ 다른 메신저(슬랙·텔레그램 등)로 자동 알림.

## 월 마감 (이카운트 '편집제한일자' 방식, 새로 만든 정산 > 월 마감)
2. **언제부터 마감할지**: 아직 아무 달도 마감하지 않았다. 추천: 10월 정산이 끝나면 2026-10 까지 마감. 마감은 그 달까지 한꺼번에 잠긴다.
3. **마감 대상**: 입금요청(주문 월 기준)·처리완료 지급요청(지급일 기준)·월 정산 현황·현금흐름표 칸. 코드 리뷰 뒤 **입금 처리·일괄 삭제·상태 변경·새 등록·주문번호 옮기기까지 모두 막았다**(이카운트처럼 마감 숫자가 흔들리지 않게). 마감한 달의 요청을 늦게 입금 처리해야 하면 대표가 그 달 마감을 잠깐 풀어야 한다 — 불편하면 '입금 처리만 허용'으로 바꿀 수 있음.
4. **점검의 '확인 필요' 건수**는 달과 상관없이 열린 질문 전체를 센다(질문에 달 정보가 없는 것이 많음).
5. **지급요청**: 확인·허가 뒤 금액이나 계좌가 바뀌면 상태가 '요청'으로 돌아가 다시 확인받게 했다(이카운트의 '수정 시 전표상태' 방식). 그대로 둘지.
6. **메신저 공유함(관리/설정 › 메신저 공유)**: 입금요청 등록·입금 완료·지급요청 등록/확인/허가 필요/지급 완료·월 마감이 자동으로 쌓이고, 자금 화면의 [공유함에 올리기]로 일일 보고도 올린다. 누가 볼 수 있나: 대표·입금요청/지급요청/자금 보기 권한자. 알림 종류를 줄이거나 늘릴지.
7. 채널톡 자동 발송을 켜게 되면: 처음엔 '시험'(대표 계정에만 공지)으로 확인 → '실제'(팀챗 그룹 24726). 내 매니저 ID 는 키가 생긴 뒤 조회해서 넣는다.

## 보안 보완
8. **입금요청·브랜드·단가표 쓰기 API 에 서버 권한 검사를 넣었다.** 지금까지는 화면에서 버튼만 숨기고 서버는 확인하지 않아, 권한이 없는 계정도 직접 호출로 등록·수정·삭제할 수 있었다. 지금 활성 계정 3개(대표·매니저·오퍼레이터)는 이 메뉴 권한이 다 있어 업무에 영향 없음(오퍼레이터는 입금완료 처리 권한만 없음 — 원래 화면에서도 숨겨짐). 새 직원 계정을 만들 때 권한표대로 실제로 막힌다는 점만 알아 두면 된다.

## 이카운트 참고 중 보류한 것 (docs/v2/ecount-applied.md)
9. **거래처 원장 일원화**: 받을 돈·줄 돈을 원장 테이블 하나에서 계산하는 방식(이카운트 핵심). 지금은 화면에서 모아 보여 주기만 한다. 할지 여부.
10. **주문매칭 합계 제약**: 한 은행 입금에 매칭한 금액 합계가 입금액을 넘지 못하게. 매칭 화면을 같이 보고 정하기.
11. **월 정산 현황 '확인' 체크를 마감 점검과 묶을지**: 이카운트는 미반영이 0일 때만 마감. 지금은 0이 아니어도 대표가 이유를 남기면 마감되게 했다.
12. **삭제된 입금요청 되돌리기 권한**: 지금은 '삭제' 권한자. 입금완료였던 건을 되돌리면 입금완료가 다시 생기는 셈이라 '입금완료' 권한도 요구할지.
13. **현금흐름표 클로브 실제값 가져오기**는 마감한 달에도 실제 입출금을 채운다(실제 거래 기록이라 그대로 둠). 막을지.
14. **v2 에서 시험 삼아 한 입금 처리**: 위 목록처럼 v2 에서 입금완료로 바꾼 기록(결제 로그)이 v2 에만 남아 있다. 입금 상태·일시·금액은 매일 새벽 pay 값으로 맞추게 했지만(실제 업무가 pay 에서 일어나므로), v2 에서 만든 결제 로그는 남는다. 전환 전에 정리할지 알려 주세요(지금 4건 내외).

## 전환(배포) 절차에 꼭 넣을 것
15. **카페24·클로브 연결은 운영(pay) 것을 그대로 옮긴다.** v2 데이터는 토큰을 비워 두었고(운영 토큰이 갱신되며 끊기지 않게), 야간 합치기도 이 두 항목은 가져오지 않는다. 전환할 때 운영 DB 의 `cafe24`·`clobe` 상태를 덮어쓰지 말 것. v2 컨테이너에는 카페24 앱 키(CAFE24_*)도 없다.
