# 이카운트(ECOUNT) 참고 — 우리 시스템에 반영한 것 (2026-11-16)

조사 원문: `docs/v2/ecount-study.md` (공식 기능 페이지 27개 + 업데이트 공지 + 실무 블로그).
원칙: 이카운트 메뉴를 다 따라 하지 않고, 지금 쓰는 메뉴를 더 안전하고 덜 번거롭게 만드는 것만.

| # | 이카운트 방식 | 우리 상태 | 한 일 / 남은 일 |
|---|---|---|---|
| 1 | 편집제한일자(마감) | **적용** | 정산 › 월 마감. 마감한 달까지의 입금요청 수정·삭제·되돌리기, 처리완료 지급요청, 월 정산 현황, 현금흐름표 칸을 서버가 거부. 해제는 대표만, 이유 기록. |
| 2 | 미○○ 현황으로 마감 | **적용** | 월 마감 점검표: 입금 안 된 입금요청, 처리 안 된 지급요청, 월 정산 미확인·미발송·시트 차이, 열린 확인 필요, 입금기한 지난 판매 미수, 마이너스 재고. 0건이 아니면 대표가 이유를 남기고 마감(우리 규모에 맞게 강제 대신 기록). |
| 3 | 거래처별 채권·채무 잔액 | 부분 적용 | 거래처 화면 개요에 받을 돈(판매 미수·기한 지남)·줄 돈(생산비 미지급)·처리 전 지급요청·브랜드 채권잔액. **원장 테이블 하나로 일원화는 보류**(입금요청·생산비·판매주문·회생에 흩어진 자료를 옮기는 큰 공사 — 대표 결정 필요). |
| 4 | 확인(승인) 후 수정 시 상태 | **적용** | 지급요청: 확인·허가 뒤 금액/계좌가 바뀌면 '요청'으로 돌아가 다시 확인. 처리완료 건 금액·계좌는 처리 권한자만(기존) + 마감 달은 아무도. |
| 5 | 앞 문서 불러오기·진행상태 | 이미 있음 | 판매 주문 단계(받음→명세서→발송→계산서→입금). 행 단위 '남은 수량'(부분 출고)은 쓰는 일이 생기면. |
| 6 | 데이터 추적·삭제 취소 | **적용** | 이력은 변경 전/후를 이미 남김. 입금요청 '삭제된 요청'에서 되돌리기 추가(삭제 전 상태로). |
| 7 | 중복 입력 방지 | 부분 적용 | 입금요청 주문번호 중복은 기존에 막음. 지급요청: 같은 계좌·같은 금액이 14일 안에 있으면 한 번 더 확인. 주문매칭 '한 입금의 매칭 합계 ≤ 입금액' 제약은 보류(매칭 화면 검토 후). |
| 8 | 거래처별 단가·최근 단가 | 이미 있음 | 판매처별 가격 + 적용일 예외, 예전 명세서 단가 자동 채움. |
| 9 | 수불 이벤트 재고·BOM | 이미 있음 | 입출고 기록 기반 재고, BOM 소모, 마이너스 표시 → 마감 점검에 연결. |
| 10 | 자금 계획 자동 생성 | 이미 있음 | 입금요청·지급요청·생산비·대출·회생에서 일정 자동 생성, 현금흐름표. |
| + | 대시보드 미결 알림 | **적용** | 대시보드 '오늘 할 일': 입금 대기, 허가 필요·확인 대기·지급할·기한 지난 지급요청, 기한 지난 판매 미수, 확인 필요, 안 보낸 메신저 알림, 지난달 마감 전. 권한에 맞게만 보임. |
| + | 알림(푸시·메일) | **적용(복사 방식)** | 메신저 공유함. 채널톡 무료 플랜은 Open API 불가 → [복사]로 팀챗에. 키·유료 플랜이 생기면 설정에서 켬. |
| + | 사용자별 권한 | **보완** | 입금요청·브랜드·단가표 쓰기 API 에 서버 권한 검사(전에는 화면에서만 숨김). |
