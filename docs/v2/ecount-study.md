# 이카운트(ECOUNT) ERP 연구: 우프컴퍼니 ERP에 가져올 것

조사일 2026-11-16. 출처는 이카운트 공식 기능 소개 페이지(ecount.com/kr/ecount/product/*), 공식 업데이트 공지(system-upgrade-view),
실무 블로그(rgleetax.co.kr 세무 블로그, jungwonlabs 이카운트 팁)다. 공식 교육 교재 PDF(download.ecounterp.com)는 받았지만
이 맥에 PDF 텍스트 추출 도구가 없어서 본문을 읽지 못했다(검색 결과 요약만 썼다).
- 공식 기능 페이지는 마케팅용 요약이라 세부 동작(결재 후 수정 가능 여부, 6가지 전표상태관리유형의 내용 등)은 확인하지 못했다.
- 확인하지 못했는데 추론한 내용은 **(추정)**으로 표시했다. 찾지 못한 기능은 "확인 안 됨"으로 적었다.

## 0. 이카운트 설계의 뼈대 (모든 모듈 공통)

1. **한 번 입력, 여러 곳 반영.** 거래는 재고 메뉴(판매입력/구매입력)에서 한 번만 입력한다. 저장하는 순간 재고 수량,
   거래처 채권·채무, 거래명세서가 같이 바뀐다. 회계 전표는 그 입력을 "회계반영"해서 만든다.
   실무 블로그는 판매입력과 매출전표를 따로 넣으면 매출과 거래처 잔액이 두 배가 된다고 가장 많이 경고한다.
2. **앞 문서를 불러와서 다음 문서를 만든다(불러오기).** 견적서→주문서→판매(출고)→회계반영 순서이고,
   구매는 발주서→구매(입고)다. 출하는 판매→출하지시서→출하 전표→출고증 순서다.
   불러올 때 앞 문서의 **진행상태**를 "완료"로 바꾸며, 이 동작은 입력화면 Option의 "진행상태변경설정"에서 기본값으로 정해 둘 수 있다.
   선택한 건만 바꾸는 '변경'과 불러온 전부를 바꾸는 '자동변경'이 있다.
3. **'미○○' 현황으로 빠진 건을 관리한다.** 미입고(발주 대비), 미출하(출하지시 대비), 수주 대비 납품 수량, 회계미반영현황(판매/구매),
   세금계산서 미발행 현황 같은 화면이다. 실무 월 마감은 이 화면들이 "0건"인지 보는 것으로 시작한다.
4. **확인(승인)한 것만 장부에 반영한다.** 미확인 전표와 확인 전표를 나누고, 확인 권한은 사용자 ID별로 준다.
   2025년 공지에 따르면 확인 권한, 확인 절차, 수정 시 전표 상태를 묶어 "전표상태관리유형" 6가지 중 하나를 고르는 방식으로 바뀌었다.
   6가지가 각각 무엇인지는 확인 안 됨.
5. **마감은 날짜 하나로 잠근다(편집제한일자).** 이 날짜 이전 자료는 조회만 되고 입력·수정·삭제가 막힌다.
6. **추적성.** 회계·재고 전표의 입력·수정·삭제 이력(작성자, 작성일, 수정·삭제일)을 남기고, 삭제는 "삭제 취소"로 되돌린다.
   보고서 숫자의 하이퍼링크를 누르면 최초 입력 전표로 간다.

## 1. 구매 (발주 → 입고 → 구매전표)

**(a) 흐름**
- 발주서는 발주계획, 주문, 단가요청에서 불러와 만든다. 품목마다 납기일자를 따로 둔다.
- 구매(입고) 전표는 발주서나 주문서를 불러와 만든다. 저장하면 재고가 늘고 거래처 채무가 자동 계산된다.
  지급을 입력하면 채무가 줄어든다.
- 미입고 현황은 발주 수량 대비 아직 들어오지 않은 수량이다. 이 화면에서 바로 재입고 처리를 한다.
- 이카운트를 쓰는 거래처가 보낸 거래명세서 이메일로 구매 전표를 자동 생성한다(여러 품목을 한 장 또는 각각).

**(b) UX**
- 납기일자 검색과 그달 발주 기한을 보여 주는 달력형 일정표.
- 발주서 인쇄와 이메일·SMS·카카오톡·팩스 발송, 이메일 수신 여부 확인.
- 엑셀 대량 업로드, 바코드 입고, 일자·품목·거래처·담당자별 집계, 거래처관리대장(일자별 구매·지급·미지급) 공유.

**(c) 우리 메뉴 적용**
- [High] 명세서·발주서 + 생산·재고·생산비: 발주서 행마다 `received_qty`를 두고 "미입고" 목록을 만든다.
  공장 생산 입고를 발주서에서 불러오게 한다. 지금은 발주서 PDF와 생산비 장부가 따로 놀 가능성이 높다 (추정).
- [Med] 발주서 발송 기록: 언제, 누구에게, 어떤 채널로 보냈는지 남긴다(이카운트는 수신 확인까지 한다).
- [Low] 납기 달력.

**(d) 이카운트가 막는 위험**
- 발주한 뒤 입고 누락, 입고는 됐는데 채무 미반영, 같은 입고 이중 입력. 이 세 가지는 불러오기와 진행상태가 막는다.

## 2. 판매 (견적/주문 → 출하 → 판매전표 → 회계)

**(a) 흐름**
- 견적서→주문서(불러오기)→판매입력(출고)→회계반영 순서다. 주문서는 판매, 구매, 발주, 생산과 연결된다.
- 판매를 저장하면 재고가 줄고, 거래처 미수금이 늘고, 거래명세서가 생긴다.
- 회계반영 방식
  - 건별
  - 판매일괄회계반영: 미반영 판매를 조건으로 조회해 한 장의 회계전표로 만든다. 월 합산 세금계산서용이다.
  - 일부반영: 특정 거래처의 일부 내역만 반영한다.
  - 매출전표Ⅰ(계정설정대로 자동 분개)과 매출전표Ⅱ(분개 직접 지정)가 있다.
- 반품은 판매입력에 마이너스 수량으로 넣는다. 이미 국세청에 신고된 매출전표는 삭제할 수 없어서 수정세금계산서로 처리한다.
- 오더관리: 주문서를 중심으로 업무 단계를 최대 10단계까지 등록한다. 단계마다 ERP 메뉴와 담당자를 연결하고,
  단계가 끝나면 다음 담당자에게 이메일·SMS·카카오톡으로 알린다. 조회 화면에서 메뉴를 옮기지 않고 바로 처리한다.
- 출하: 판매를 불러와 출하지시서를 만들거나 판매 저장 시 자동 생성한다. 출하지시서를 불러와 출하 전표를 넣으면
  출고증이 자동으로 만들어진다. 미출하현황, 출하현황, 출하지시서 완료 표시가 있다.

**(b) UX**
- 판매 입력 화면에서 저장 전에 원가·이익·이익률을 보여 준다(이익관리).
- 거래처를 고르면 등록 정보와 미수 잔액이 자동으로 채워진다(사용기능 최적화).
- 견적서·주문서 양식을 각각 최대 50개 만들고, 이미지·납기일자·요청사항 같은 항목을 더한다.
- 거래명세서 건별·일괄 발송(이메일·카카오톡·SMS·팩스), 기간 내 여러 전표를 한 장으로 출력, 미수금·계좌번호 표시.
- 단축키(jungwonlabs): Enter로 다음 칸, 입력순서 번호(0이면 건너뜀), F4로 공급가·부가세 분리, `+`로 000 입력.
- 자동추천관계설정: 출하창고를 고르면 과거 판매를 보고 거래유형을 추천한다.
- 전표 알림설정: 판매 전표가 생성·수정·삭제되면 알림을 보낸다.

**(c) 우리 메뉴 적용**
- [High] 판매 주문·가격 → 명세서: 명세서를 판매 주문에서 "불러오기"로 만들고, 주문 행마다 남은 수량(`ordered - shipped`)을 관리한다.
  진행상태(대기/부분/완료)는 사람이 누르지 않고 남은 수량으로 계산한다.
- [High] 월 정산 현황 체크리스트: "미반영 0건" 게이트를 둔다. 월 정산에 안 들어간 cafe24 주문·입금·요청 건수를
  보여 주고, 0건이 아니면 "확인"을 막거나 경고한다.
- [Med] 판매 주문 입력 시 거래처 미수 잔액과 마진 미리보기를 보여 준다.
- [Med] 명세서 일괄 발송과 발송 이력(월 정산 현황의 "명세서 발송" 체크와 연결).
- [Low] 단계형 오더 진행판(최대 N단계, 담당자, 다음 사람 알림). 지급요청 결재와 판매 주문 처리에 같은 엔진을 쓸 수 있다 (추정).

**(d) 막는 위험**
- 이중 매출: 판매입력과 매출전표를 각각 넣는 것. 우리로 치면 cafe24 주문 매칭과 수기 매출을 둘 다 잡는 경우다.
- 출고는 했는데 명세서·세금계산서를 안 보낸 건(미발행 현황).
- 신고가 끝난 매출을 지우는 것(삭제 대신 수정 문서로 처리).

## 3. 재고 (수불부, 창고, 생산입고/소모, BOM)

**(a) 흐름**
- 판매·구매·생산 전표가 재고를 자동으로 바꾸고, 재고수불부는 그 전표들로 자동 생성되는 보고서다. 재고를 따로 입력하지 않는다.
- 창고는 무제한으로 등록한다. 창고간 이동을 기록하고 창고별 수불을 실시간으로 본다.
- 재고 실사: 품목·창고별 실제 수량을 넣으면 프로그램이 차이를 계산한다.
- BOM: 제품 하나에 드는 원·부재료 수량(다단계, EA/SET/KG 단위)을 정한다. 엑셀로 올릴 수 있다.
  생산입고를 입력하면 완제품 재고가 바로 늘고, 생산 입력 때 실제 소모 수량을 넣는다.
  BOM 기준 소모와 실제 소모(원가)를 나란히 비교한다.
- 이익관리: 판매·구매 기록으로 원가·이익·이익률을 자동 계산한다. 원가 방식(선입선출, 입고단가)을 고른다.
  제조업은 월마다 "원가생성"을 돌린다.
- 외주 생산업체가 온라인수발주시스템에 로그인해 자재 출고와 생산품 입고 수불을 직접 본다.

**(b) UX**
- 재고현황 보고서에 품목 이미지와 가용재고를 더하고, 조건을 만족하면 자동으로 보낸다.
- 보고서 양식별로 볼 수 있는 ID를 제한하고, 엑셀·PDF로 내보낸다.

**(c) 우리 메뉴 적용**
- [High] 생산·재고·생산비: 재고 숫자를 직접 고치지 않고 "수불 이벤트"(생산입고, 출고, 이동, 실사조정)를 쌓아서 계산한다.
  실사는 실제 수량을 입력하면 차이만큼 조정 이벤트를 만든다.
- [Med] 원부자재 + 생산: 제품별 BOM을 두고 생산입고 때 자재 소모 이벤트를 자동으로 만든다. BOM과 실제 소모가 다르면
  차이를 보여 준다. 생산비 장부의 단가 근거가 된다.
- [Med] 공장(납품지·공장)을 "창고"로 본다. 공장별 재고, 공장 간 이동 (추정: 우리 공장 수가 적다면 Low).
- [Low] 공장이 자기 수불을 보는 외부 포털.

**(d) 막는 위험**
- 마이너스 재고. 실무 체크리스트 8번은 월말에 마이너스 품목이 없는지 보라고 한다. 원인은 대개 구매(입고) 입력 누락이다.
  이카운트에 마이너스 재고 차단 설정이 있는지는 확인 안 됨. 체크리스트에서는 사후 점검으로 다룬다.
- 재고 숫자를 직접 고쳐 근거가 사라지는 문제.
- 샘플·자가사용·불량 재고 미입력(체크리스트 9번, 자가사용·불량처리 메뉴).

## 4. 거래처 관리 (단가, 원장, 채권/채무, 미수/미지급)

**(a) 흐름**
- 거래처에는 사업자번호, 주소 같은 기본 항목과 회사가 정한 추가 항목이 있다. 거래처그룹(매출처/매입처, 지역 등)으로 묶는다.
  사업자번호는 홈택스 자료와 대조하는 기준이라 정확해야 한다.
- 판매는 미수금을 늘리고 수금은 줄인다. 구매는 채무를 늘리고 지급은 줄인다. 거래처별·담당자별로 판매, 수금, 미수 내역을 본다.
- 여신한도: 거래처별로 한도를 두고, 넘으면 경고하고 입력을 막을 수 있다. 연체 기간도 관리한다.
- 보고서: 거래처관리대장(일자별 구매·지급·미지급, 이메일·SMS·카카오톡 공유), 채권채무회수기간표, 잔액분석표, 월별매입매출집계표.
- 대사: 영업부서 매출과 회계부서 매출이 같은지 비교한다. "이카운트 VS 홈택스 자료비교"로 홈택스에만 있는 세금계산서를 찾는다.

**(b) UX**
- 거래처를 고르면 연락처, 담당자, 미수 잔액이 입력 화면에 자동으로 뜬다.
- 품목중심입력과 거래처중심입력: 상단 검색에서 거래처 하나를 중심으로 전표와 보고서를 모아 본다.
- 거래처가 포털에서 거래내역, 거래명세서, 세금계산서를 직접 본다(온라인수발주).

**(c) 우리 메뉴 적용**
- [High] 거래처(사업자) hub에 "거래처 원장" 탭: 판매 주문/명세서(+), 입금(-), 입금요청 선지급(브랜드에 대한 채무 상계), 지급(+/-)을
  한 줄씩 쌓아서 누적 잔액을 보여 준다. 시작 시점 기초잔액을 넣는다.
- [High] 월 정산 현황의 "미수 회수"를 이 원장에서 계산한다. 정산 보드와 원장의 잔액이 다르면 표시한다.
- [Med] 채권 연령표(30/60/90일). 이카운트의 "채권채무회수기간표"에 해당한다.
- [Med] Clobe 세금계산서와 우리 명세서 대조(이카운트 VS 홈택스 비교에 해당). 사업자번호로 맞춘다.
- [Low] 여신한도 경고(B2B 채널 판매 주문 저장 시).

**(d) 막는 위험**
- 잔액을 여러 화면이 따로 계산해서 숫자가 서로 다른 문제. 이카운트는 모든 잔액이 전표에서 나온다.
- 같은 사업자가 두 번 등록되는 문제. 사업자번호를 기준 키로 쓰는 이유다. 중복 차단 기능이 있는지는 확인 안 됨 (추정).

## 5. 회계 연동, 자금, 계좌

**(a) 흐름**
- 판매·구매가 회계 매입매출과 연동되고 채권채무에 자동으로 들어간다. 계정은 [Option] › 계정설정에서 정한다.
- 은행계좌통합관리: 여러 은행 계좌의 입출금을 실시간으로 모아 한 화면에 보여 주고, 모은 내역을 회계 전표로 저장한다.
  지출결의와 급여를 불러와 계좌이체를 실행하고, 이체 완료 여부를 이카운트에서 본다(장부와 이체 금액이 어긋나는 것을 막는다).
- 자금계획: 판매·구매 시 수금·지급 예정일을 등록한다. 임대료, 관리비, 공과금, 급여 같은 반복 고정비를 미리 등록한다.
  일/월/년 단위로 미래 자금을 예측하고 달력에 표시한다. 수금, 지급, 어음 만기를 한 곳에서 본다.
- 경영자보고서: 자금일보, 자금현황표, 자금증감내역, 월별손익분석. 경영요약보고서를 정한 시간에 이메일로 받는다.

**(b) UX**
- 달력형 자금 계획, 정기 메일 보고서, 보고서 숫자에서 원전표로 이동.

**(c) 우리 메뉴 적용**
- [High] 자금 › 자금 일정: 입금요청(지급 예정일), 지급요청(승인된 건의 지급일), B2B 미수(수금 예정일), 대출·회생 상환일을
  자동으로 끌어와 일자별 예정 입출금을 만든다. 손으로 다시 적지 않게 한다.
- [Med] 반복 고정비 템플릿(월세, 급여, 보험, 회생 변제금)으로 미래 일정을 자동 생성한다.
- [Med] 지급요청 "지급 완료"를 Clobe 출금 내역과 맞춘다(이카운트의 이체 완료 확인에 해당).
- [Low] 매일 아침 자금일보 메일·메신저 발송.

**(d) 막는 위험**
- 결재한 금액과 실제 이체 금액이 다른 것, 계좌 내역이 전표가 안 된 채 남는 것(체크리스트 7번, 입/출금계좌 조회의 미처리 건),
  세금계산서로 이미 잡은 거래를 은행 내역으로 다시 입력하는 이중 입력.

## 6. 결재 (전자결재, 확인/승인)

**(a) 흐름**
- 기안서 양식마다 결재 방식과 결재선을 정한다. 회사 공통 양식함, 로고, 개인 서명 등록.
- ERP 전표(지출결의, 견적, 근태 등)를 기안에 첨부하고, 결재가 끝나면 그 전표가 ERP에 자동 반영된다.
- 비용 전표는 결재권자 확인을 거쳐야 장부에 들어간다. 미확인 전표와 확인 전표를 나눠 관리한다.
- 예산(부서·프로젝트·계정별)을 넘으면 알림을 보내고 전표 입력을 막을 수 있다.
- 기안이 올라오면 메모나 모바일 푸시로 알리고, 모바일 앱에서 결재한다. 단계별 진행 상황을 실시간으로 본다.
- 확인 안 됨: 합의, 전결, 결재 후 수정 불가 여부. 2025년 "전표상태관리유형" 공지가 "수정 시 전표 상태"를 유형에 포함한다고
  하므로, 확인된 전표를 고치면 상태가 바뀌는(예: 미확인으로 되돌아가는) 선택지가 있을 것으로 본다 (추정).

**(c) 우리 메뉴 적용**
- [High] 지급요청: 승인 뒤에 금액·계좌·거래처를 고치면 승인이 자동으로 풀리고(재무 확인 단계로 되돌아감) 이력이 남게 한다.
  "승인된 것만 지급 가능, 지급 목록에는 승인 시점 금액이 고정" 규칙.
- [Med] 결재선 템플릿: 요청 종류와 금액 구간별로 결재선을 정한다(예: 100만 원 이하는 재무 확인만) (추정, 우리 정책 결정 필요).
- [Med] 입금요청과 월 정산 "확인"에도 같은 상태 기계(작성→확인→승인→잠금)를 재사용한다.
- [Low] 예산 한도 경고.

**(d) 막는 위험**
- 승인 뒤 몰래 금액 수정, 미승인 지출이 장부에 섞이는 것.

- 확인 안 됨: 검색조건 저장, 이전 버전과 비교, 별도 대시보드 화면.

**(c) 우리 메뉴 적용**
- [High] 이력: 이력을 "누가 무엇을 바꿨나" 목록에서 문서별 타임라인으로 바꾸고, 변경 전/후 값을 남긴다.
  삭제는 소프트 삭제로 하고 아카이브에서 되돌린다.
- [Med] 보고서(월 정산 현황, KPI·손익, 자금) 숫자를 누르면 그 숫자를 만든 원 문서 목록으로 간다.
- [Med] 엑셀 업로드 공통 컴포넌트: 미리보기 → 행별 오류 사유 → 통과한 행만 반영. 다운로드 권한.
- [Med] 필수항목과 저장 전 검증을 서버에서 한다.
- [Low] 검색조건 저장(이카운트에서 확인은 못 했지만 우리 표 화면에 유용) (추정).

## 11. 우선순위 Top 10

1. **월 마감 잠금 (편집제한일자)**: 정산 › 월 정산 현황, 경영관리 › 자금, 거래 전반
   - `closing_periods(month, locked_at, locked_by, unlocked_at, unlock_reason)`.
   - 저장 API 공통 미들웨어: 문서 날짜 ≤ 잠금월 말일이면 거부한다(관리자 화면에서도).
   - 해제는 대표 권한만 가능하고 사유는 필수이며 이력에 남긴다. 월 정산 현황의 "명세서 발송 완료"를 잠금 조건으로 연결한다.
2. **마감 게이트: "미반영 0건" 점검판**: 정산 › 월 정산 생성/현황, 확인 필요
   - 매칭 안 된 cafe24 주문, 정산에 안 들어간 입금, 처리 안 된 입금요청·지급요청, 미발송 명세서, 마이너스 재고를 월별로 집계한다.
   - 브랜드 체크리스트의 "확인" 버튼은 이 카운트가 0일 때만 켜고, 0이 아니면 사유를 입력해야 넘어간다.
3. **거래처 원장 하나로 모든 잔액 계산**: 거래 › 거래처(사업자) hub, 정산
   - `ledger_entries(partner_id, date, type[sale|receipt|prepay|deduction|payment|adjust], amount, source_type, source_id)`.
   - 기초잔액 행. 정산 보드의 미수 회수, 입금요청 상계, 판매 미수는 모두 이 테이블 합계로만 보여 준다.
   - 이 테이블은 원 문서 저장 시 트리거로만 쓰고, 직접 수정은 막는다.
4. **승인 상태 기계 + 승인 후 수정 시 승인 해제**: 결제/구매 › 지급요청, 입금요청
   - `status: draft → requested → finance_confirmed → ceo_approved → paid`.
   - approved 이후 금액·계좌·수취인이 바뀌면 `finance_confirmed` 이전으로 되돌리고 승인자에게 알린다.
   - `paid`는 수정할 수 없고 취소 문서로만 되돌린다. 지급 시점 금액은 스냅샷으로 남긴다.
5. **문서 연결(불러오기) + 남은 수량으로 계산하는 진행상태**: 판매 주문·가격 → 명세서·발주서, 생산·재고
   - 명세서 행에 `source_order_line_id`를 둔다. 주문 행 `remaining = qty - sum(linked statement qty)`.
   - 상태는 저장하지 않고 계산한다(0이면 완료, 일부면 부분). "미출고/미입고" 목록은 remaining > 0 필터로 만든다.
6. **이력: 문서별 변경 전/후 + 소프트 삭제 + 원 문서 추적**: 관리/설정 › 이력, 아카이브
   - `audit_log(entity, entity_id, action, before_json, after_json, actor, at)`.
   - 문서 상세 화면에 타임라인 탭. 삭제는 `deleted_at`으로 하고 아카이브에서 복원한다.
   - 보고서 숫자 → 원 문서 목록 링크(source ids 전달).
7. **원천 키 중복 방지 (이중 매출·이중 입금 차단)**: 결제/구매 › 주문매칭, 정산 › 월 정산 생성, 자금
   - cafe24 주문번호, Clobe 은행 거래 ID, 세금계산서 승인번호에 유일 제약을 건다.
   - 한 입금은 매칭 합계가 입금액을 넘지 못하게 하고(`sum(match.amount) ≤ deposit.amount`), 수기 매출을 입력할 때 같은 날짜·금액·거래처의 자동 건이 있으면 경고한다.
8. **단가 이력과 주문 시점 단가 고정**: 판매 주문·가격, 자사몰관리 › 단가표
   - `prices(item_id, channel_or_partner_id, price, valid_from, created_by)`. 조회 시 valid_from ≤ 주문일인 최신 행을 쓴다.
   - 주문 행에 `unit_price`를 복사하고, 단가표 값과 다르면 표시한다. 입력 때 "최근 거래 단가 3건"을 보여 주고, 단가 수정 권한을 따로 둔다.
9. **수불 이벤트 기반 재고 + BOM 소모**: 거래 › 생산·재고·생산비, 원부자재
   - `stock_moves(item_id, location_id, qty(+/-), type[production_in|consume|ship|transfer|count_adjust], source)`.
   - 재고는 합계로 계산한다. 생산입고 시 BOM으로 자재 소모를 만들고, 실제 수량으로 고칠 수 있게 한다.
   - 실사는 조정 이벤트로 넣는다. 결과가 마이너스이면 경고하고 마감 점검판에 올린다.
10. **자금 일정 자동 생성 + 반복 고정비**: 경영관리 › 자금
    - 입금요청 예정일, 승인된 지급요청 지급일, B2B 미수 예정일(명세서일 + 거래처 결제조건), 대출·회생 상환표를 `cash_schedule`로 자동 생성한다(source 링크 포함).
    - 반복 템플릿(월세, 급여 등)도 넣는다. 실제 Clobe 거래와 매칭되면 "실행됨"으로 표시하고, 예정과 실적의 차이를 일별 표에 보여 준다.
