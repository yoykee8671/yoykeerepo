# 상품동기화 — 공급사 공식몰 ↔ 우프(카페24)

## 왜

우프는 공급사 입점형 종합몰이다. 재고는 공급사가 각자 어드민에서 관리하지만 제때
반영되지 않아 품절 상품이 팔리거나, 재입고된 상품이 계속 품절로 남는다. 공식몰을
직접 읽어 우프와 비교하고, 사람이 확인한 뒤 버튼으로 반영한다.

## 흐름

1. **수집** — 본사 몰의 진열 카테고리(`categoryNos`)를 모두 훑고, 상세 페이지마다
   카페24가 심어 둔 변수(`product_name`, `product_price`, `option_stock_data`,
   `is_soldout_icon`)를 읽는다. 스킨이 달라도 이 변수는 같다.
2. **우프 조회** — 연결된 우프 상품을 카페24 Admin API로 품목(variants)까지 읽는다.
3. **비교** — 우프가 본사와 다른 점(issue)을 만든다. "지난번과 달라졌나"가 아니라
   "지금 같은가"를 본다 — 그래야 처음부터 어긋나 있던 것도 잡힌다.
4. **반영** — 화면에서 고른 issue 를 상품별로 묶어 카페24에 쓴다.

자동 확인: 매일 09시·17시(한국시간) 이후 첫 확인(10분 간격) 때 한 번.
서버가 그 시각에 꺼져 있었으면 켜진 뒤 따라잡는다.

## 판정 규칙 (MUNIKUND 168개 실측, 2026-10-15)

| 상태 | 본사 표시 |
|---|---|
| 상품 전체 품절 | `is_soldout_icon = 'T'` (옵션은 판매중으로 남아 있을 수 있음) |
| 옵션 품절(판매안함) | `is_selling = 'F'` |
| 옵션 품절(재고 소진) | `is_selling = 'T'` 그대로 + `stock_number: 0` + `is_auto_soldout = 'T'` — **239개가 이 방식** |
| 판매중 | 위에 해당 없음 (재고 수량은 공개되지 않음) |

우프도 공급사들이 "재고관리 사용 + 수량 0 → 자동 품절"로 쓰고 있어서 같은 방식으로 반영한다.

- 품절 반영: `use_inventory T, display_soldout T, quantity 0`
- 재입고: `quantity = restockQuantity(기본 99), selling T, display T`
- 판매가: 본사 **정가**(`product_price`). 본사 할인가는 따르지 않는다.
- 옵션 추가금: 본사 `stock_price`.

## 연결표

우프 상품번호 → `{ sourceNo, sourceFilter, valueMap, optionMap }`.

- 우프 상품명은 한글 번역명이라 이름으로 자동 매칭하지 않는다. 기존 72개는
  `lib/product-sync-seed.mjs` 로 한 번 넣었다(처음 실행 때만).
- 본사 한 상품(색상×사이즈)을 우프가 색상별 여러 상품으로 나눈 경우
  `sourceFilter`(예: `M-Band Yellow`)로 그 색상 옵션만 비교한다.
- 옵션값 번역은 브랜드 공통 `valueMap`(Bloom Blue = 블룸 블루), 상품별 예외는 링크의 `valueMap`/`optionMap`.
- 괄호 안 안내 문구("1호 (10/21 순차배송)")는 짝을 못 찾을 때 빼고 다시 비교한다.

초기 연결 때 발견한 것: 우프 26156 "버그가드 티 (블룸 블루)"는 실제 캔디 오렌지 상품(썸네일 대조) — 본사 1560에 연결, 우프 상품명 수정 필요.

## 신상품 등록

후보: 연결되지 않은 본사 진열 상품 중 본사 등록일(추정)이 `recentDays`(기본 92일) 이내.
등록일은 화면에 없어서 상세이미지 경로 날짜(`NNEditor/20261001/`)와 대표·추가이미지 업로드 월 중 가장 이른 것으로 추정한다.

등록 순서 (작업으로 돌고 화면은 진행 상황을 묻는다 — 앞단이 100초에 끊으므로):

1. 본사 상품을 다시 읽는다.
2. 대표이미지: 흰 배경(테두리 97% 이상이 248+)이면 `#F7F7F7` multiply, 정방형 아니면 흰 여백으로 채움.
3. 상세이미지: 내려받아 JPG/PNG/GIF·5MB 이하로 맞춘 뒤(`scripts/product_image.py normalize`) `POST /products/images` 로 우프에 올리고, 그 주소로 상세설명을 만든다.
4. `POST /products` — **미진열**, 판매가=본사 정가, 공급사·카테고리·원산지·과세는 기준 상품에서 복사, 공급가 = 판매가 × 기준 상품의 공급가/판매가.
5. 대표이미지(`/products/{no}/images`, 대표이미지 등록 A), 추가이미지(`/additionalimages`).
6. 품목별 추가금·재고(본사 품절이면 0), 본사에 없는 조합은 진열·판매 안 함.
7. 자동으로 연결표에 추가.

## 저장

`app_state` 테이블의 별도 행 `id = 'product_sync'`(로컬은 `data/product-sync.json`).
메인 상태와 나눈 이유: 스냅샷(170개)이 매 화면 로딩마다 오가지 않게, 백그라운드 저장이 사람의 저장과 낙관적 잠금에서 부딪히지 않게.

## 권한·설정

- 메뉴 권한 `productsync`: 보기 / 실행·반영. owner 외 계정은 관리자 화면에서 켜야 보인다.
- `CAFE24_SCOPE` 에 `mall.read_product,mall.write_product` 추가, 개발자센터 앱에서도 상품 권한을 켠 뒤 카페24 재연결.
- `PRODUCT_SYNC_SCHEDULE=on|off` (production 기본 on).

## 다른 브랜드 추가

본사 몰이 카페24면 `DEFAULT_SOURCES`(lib/product-sync.mjs)에 항목을 하나 더 두면 된다
(baseUrl, categoryNos, namePrefix). 카페24가 아닌 몰은 `brand-source-*.mjs` 수집기를 따로 만든다.
제공 자료(엑셀 등)로 등록하는 경로는 아직 없다.

## 로컬 시험

가짜 카페24로 돌리려면 `CAFE24_API_BASE=http://127.0.0.1:PORT` 를 준다(운영에는 두지 않는다).
