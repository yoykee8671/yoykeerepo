# 상품동기화 — 공급사 공식몰 ↔ 우프(카페24)

## 왜

우프는 공급사 입점형 종합몰이다. 재고는 공급사가 각자 어드민에서 관리하지만 제때
반영되지 않아 품절 상품이 팔리거나, 재입고된 상품이 계속 품절로 남는다. 공식몰을
직접 읽어 우프와 비교하고, 사람이 확인한 뒤 버튼으로 반영한다.

## 흐름

실행은 두 가지로 나뉜다.

**재고 확인** (매일 09·17시, 버튼 "재고 확인하기")
1. 우프와 연결된 본사 상품(약 70개)의 상세만 읽는다. 본사 전체를 매번 읽지 않는다.
2. 연결된 우프 상품을 카페24 Admin API로 품목(variants)까지 읽는다.
3. 우프가 본사와 다른 점(issue)을 만든다. "지난번과 달라졌나"가 아니라 "지금 같은가"를 본다 — 처음부터 어긋나 있던 것도 잡힌다.
4. 화면에서 고른 issue 를 반영한다. 쓰기 직전에 본사·우프를 다시 읽어 화면에서 본 값과 같을 때만 쓴다.

**신상품 찾기** (매일 1회 첫 실행 시각, 버튼 "신상품 찾기")
1. 본사 진열 카테고리의 목록 페이지만 훑어 상품번호를 모은다(상세는 안 읽음).
2. 처음 보는 번호만 상세를 읽는다. 첫 실행 때만 전체를 읽는다.
3. 신상품 화면에서 본사 등록일 기간(기본 최근 92일)으로 걸러 보여 준다.

서버가 실행 시각에 꺼져 있었으면 켜진 뒤 따라잡고, 실패하면 한 시간 뒤 다시 시도한다.

## 판정 규칙 (MUNIKUND 168개 실측, 2026-10-15)

| 상태 | 본사 표시 |
|---|---|
| 상품 전체 품절 | `is_soldout_icon = 'T'` (옵션은 판매중으로 남아 있을 수 있음) |
| 옵션 품절(판매안함) | `is_selling = 'F'` |
| 옵션 품절(재고 소진) | `is_selling = 'T'` 그대로 + `stock_number: 0` + `is_auto_soldout = 'T'` — **239개가 이 방식** |
| 판매중 | 위에 해당 없음 (재고 수량은 공개되지 않음) |

우프도 공급사들이 "재고관리 사용 + 수량 0 → 자동 품절"로 쓰고 있어서 같은 방식으로 반영한다.

- 품절 반영: `use_inventory T, display_soldout T, quantity 0`
- 재입고: `quantity = restockQuantity(기본 99), selling T, display T`
- 판매가: 본사 **정가**(`product_price`). 본사 할인가는 따르지 않는다.
- 옵션 추가금: 본사 `stock_price`.
- 옵션명: 괄호 안 안내 문구만 다를 때("1호 (10/21 순차배송)" ↔ "1호") 본사에 맞춘다(`PUT /products/{no}/options`, 품목은 초기화되지 않음). 뜻이 다른 값(블룸 블루 ↔ Bloom Blue)은 건드리지 않는다. 우프에서 일부러 다르게 둔 경우 "무시"하면 본사 문구가 또 바뀔 때만 다시 뜬다.

## 연결표

우프 상품번호 → `{ sourceNo, sourceFilter, valueMap, optionMap }`.

- 우프 상품명은 한글 번역명이라 이름으로 자동 매칭하지 않는다. 기존 72개는
  `lib/product-sync-seed.mjs` 로 한 번 넣었다(처음 실행 때만).
- 본사 한 상품(색상×사이즈)을 우프가 색상별 여러 상품으로 나눈 경우
  `sourceFilter`(예: `M-Band Yellow`)로 그 색상 옵션만 비교한다.
- 옵션값 번역은 브랜드 공통 `valueMap`(Bloom Blue = 블룸 블루), 상품별 예외는 링크의 `valueMap`/`optionMap`.
- 괄호 안 안내 문구("1호 (10/21 순차배송)")는 짝을 못 찾을 때 빼고 다시 비교한다.

초기 연결 때 발견한 것: 우프 26156 "버그가드 티 (블룸 블루)"는 실제 캔디 오렌지 상품(썸네일 대조) — 본사 1560에 연결, 우프 상품명 수정 필요.

## 신상품 등록

후보: 연결되지 않은 본사 진열 상품 중 본사 등록일(추정)이 `recentDays`(기본 92일) 이내.
등록일은 화면에 없어서 상세이미지 경로 날짜(`NNEditor/20261001/`)와 대표·추가이미지 업로드 월 중 가장 이른 것으로 추정한다.

등록 순서 (작업으로 돌고 화면은 진행 상황을 묻는다 — 앞단이 100초에 끊으므로):

1. 본사 상품을 다시 읽는다.
2. 대표이미지: 흰 배경(테두리 97% 이상이 248+)이면 `#F7F7F7` multiply, 정방형 아니면 흰 여백으로 채움.
3. 상세이미지: 내려받아 JPG/PNG/GIF·5MB 이하로 맞춘 뒤(`scripts/product_image.py normalize`) `POST /products/images` 로 우프에 올리고, 그 주소로 상세설명을 만든다.
4. `POST /products` — **미진열**, 판매가=본사 정가, 공급사·원산지·과세는 기준 상품에서 복사, 공급가 = 판매가 × 기준 상품의 공급가/판매가.
   분류는 기존 연결 상품(최근 8개)에 **공통으로** 들어 있는 분류만 넣는다 — 브랜드와 우프의 분류 체계가 달라 한 상품의 분류를 통째로 복사하면 엉뚱한 분류가 따라온다. 상품 종류별 분류는 사람이 지정한다.
   등록 직후 기본몰(1번) 외 쇼핑몰은 판매·진열을 끈다.
5. 대표이미지(`/products/{no}/images`, 대표이미지 등록 A), 추가이미지(`/additionalimages`).
6. 품목별 추가금·재고(본사 품절이면 0), 본사에 없는 조합은 진열·판매 안 함.
7. 자동으로 연결표에 추가.

## 저장

`app_state` 테이블의 별도 행 `id = 'product_sync'`(로컬은 `data/product-sync.json`).
메인 상태와 나눈 이유: 스냅샷(170개)이 매 화면 로딩마다 오가지 않게, 백그라운드 저장이 사람의 저장과 낙관적 잠금에서 부딪히지 않게.

## 권한·설정

- 메뉴 권한 `productsync`: 보기 / 실행·반영. owner 외 계정은 관리자 화면에서 켜야 보인다.
- `CAFE24_SCOPE` 에 `mall.read_product,mall.write_product` 추가, 개발자센터 앱에서도 상품 권한을 켠 뒤 카페24 재연결.
- `PRODUCT_SYNC_SCHEDULE=on|off` (production 기본 on).

## 다른 브랜드 추가

본사 몰이 카페24면 `DEFAULT_SOURCES`(lib/product-sync.mjs)에 항목을 하나 더 두면 된다
(baseUrl, categoryNos, namePrefix). 카페24가 아닌 몰은 `brand-source-*.mjs` 수집기를 따로 만든다.
제공 자료(엑셀 등)로 등록하는 경로는 아직 없다.

## 로컬 시험

가짜 카페24로 돌리려면 `CAFE24_API_BASE=http://127.0.0.1:PORT` 를 준다(운영에는 두지 않는다).

## 앤블랭크 (아임웹 공급사)

공급사마다 `platform` 이 있고, 읽는 방법만 다르다. 비교·반영·등록은 같은 코드를 쓴다.

| platform | 수집기 | 상품 목록 | 옵션·품절 | 등록일 추정 |
| --- | --- | --- | --- | --- |
| `cafe24` (MUNIKUND) | `lib/brand-source-cafe24.mjs` | 분류 목록 화면 | 상세 페이지 `option_stock_data` | 상세 이미지 경로 날짜 |
| `imweb` (앤블랭크) | `lib/brand-source-imweb.mjs` | `/sitemap.xml` | `POST /shop/load_option.cm` (조합형은 앞 값을 골라 다시 호출) | JSON-LD 썸네일 경로 `/thumbnail/YYYYMMDD/` |

아임웹 메모
- 정가는 `SITE_SHOP_DETAIL.initDetail` 의 `prod_price`. 옵션 목록에 보이는 금액은 할인 적용가라서
  추가금은 `POST /shop/select_option.cm` 의 `selected_option.price - prod_price` 로 구한다.
  보이는 금액이 같은 옵션은 추가금도 같으므로 금액 종류마다 한 번만 묻고, 다음 확인부터는
  지난 값(`displayPrice`)이 같으면 묻지 않는다.
- 품절 옵션은 클릭 코드가 없고 "(품절)" 글자만 있다. 추가금은 다른 옵션의 할인율로 거꾸로 계산한다.
  "품절 임박"은 판매 중이다.
- 재고 확인(하루 2번)은 상세 페이지(약 500KB)를 읽지 않고 옵션만 읽는다(옵션 없는 상품만 상세).
- 상품 이미지는 3:4 흰 배경 원본(`cdn.imweb.me`). 등록 때 정사각형으로 흰 여백을 붙이고 F7F7F7 multiply.
- 상세설명은 `<template id="prodDetailPC">`. 링크(`<a>`) 안 이미지(회원가입·카카오 배너)는 뺀다.
- 샌드박스(개발 환경)에서는 andblank.com 이 403(접근 제한)이지만 Render 서버에서는 열린다
  (상품동기화 `/api/product-sync/probe` 로 확인).

기존 우프 상품 연결
- 상품 연결표 → **우프 기존 상품 자동 연결 찾기**: 우프에서 이름이 `namePrefix`(앤블랭크)로 시작하고
  다른 브랜드에 연결되지 않은 상품을 본사 상품 이름과 맞춘다.
  - 이름 일치: 앞말·띄어쓰기·기호를 뺀 이름이 같음
  - 옵션으로 나눔: 우프 "… (블랙)" ↔ 본사 "…" + 옵션 블랙 → 옵션 필터 `블랙`
  - 비슷한 이름: 글자 2개 단위 유사도 72% 이상 — 미리 체크하지 않음
- 고른 것을 한 번에 연결하면(`POST /sources/:id/links/bulk`) 바로 재고 확인이 돈다.
- 본사 상품을 먼저 읽어야 하므로 처음에는 **신상품 찾기**를 한 번 돌린다.
