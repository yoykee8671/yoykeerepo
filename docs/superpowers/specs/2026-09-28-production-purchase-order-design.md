# 거래관리 > 명세서 발행 — 1단계: 생산업체 발주서 설계

## 배경

ERP를 "거래관리"라는 새 메뉴로 확장한다. 최종 목표는 세 가지 거래 유형을 모두 다루는 것:

1. **생산업체** — 공장에 완제품/원부자재 발주
2. **판매납품처** — 완제품을 납품하는 채널 (카페24로 안 들어오는 B2B 몇 곳 포함: 펫페이스/아롬나옴/로렌츠B2B)
3. **매입공급처** — 타사 제품을 매입·판매하는 경우의 공급처

이번 스펙은 **1번(생산업체 발주서)만** 다룬다. 2, 3번은 별도 스펙으로 이어간다.

배경 문제:
- 생산 원부자재는 상품마다 발주단위·리드타임·재고 시점이 제각각이라 관리가 어렵다.
- 지금은 발주서/생산개시통보서/거래명세서를 매번 구글시트에서 수기로 만든다.
- 최종적으로는 "상품화된 완제품"이 NPB 정산에서 쓰는 상품과 매칭되어야 하지만, 이번 스펙에서는 다루지 않는다(추후 별도 설계).

## 현황 조사 결과

**구글시트(생산업체 발주 현황, 25개 탭)**: 누적되는 표가 아니라 탭 하나당 문서 하나(거래처별 발주서/생산개시통보서/거래명세서가 뒤섞임). 공통 스키마 없음. 원단은 Roll(R/L) 단위, 완제품은 개수 단위처럼 품목마다 발주단위가 다르다.

**노션 DB("발주 및 정산 업체 정보 시트")**: 생산업체 전용이 아니라 전사 거래처 마스터(구분 16종: 생산/경영/세금/교육/직원/새벽배송 등). 계산서 발행 시점(14종 옵션), 발주방식, 계좌정보, 담당자, 사업자몰 로그인 아이디/비밀번호(평문)까지 저장 중.

**기존 `brands` 컬렉션**: 카페24 정산엔진(정산유형·수수료율·배송비룰·프로모션)에 깊게 결합되어 있어 생산업체 용도로 재사용 불가로 판단.

## 결정 사항

- `partners`(거래처관리)는 이번 ERP 3분류(생산업체/판매납품처/매입공급처)에만 쓴다. 노션의 전사 거래처(경영/세금/교육/직원 등)는 흡수하지 않는다 — 별도로 유지.
- 원부자재/발주 품목 관리는 **하이브리드**: 카탈로그에서 선택하거나 없으면 즉석 입력, 저장 시 카탈로그 등록 제안. 기존 판매 품목 쪽의 "카탈로그에 없는 품목 저장 시 등록 제안" 패턴(`feat(prices): catch unmatched line items at request save and offer to catalog them`, 커밋 946258f)을 원부자재용으로 재사용한다.
- 문서 발행은 1차로 **엑셀만** 지원한다(기존 `scripts/settlement_excel.py`의 openpyxl 방식 재사용). PDF는 필요해지면 추후 추가.

## 데이터 모델

### `partners` (거래처)
신규 컬렉션. 이번엔 `category: "production"`만 실제로 쓰지만, 스키마는 세 분류를 함께 수용한다.

| 필드 | 설명 |
|---|---|
| `id` | |
| `category` | `production` \| `sales` \| `purchase` |
| `name` | 거래처명 |
| `businessName` | 상호명 |
| `businessNumber` | 사업자등록번호 |
| `representativeName` | 대표자명 |
| `address` | 주소 |
| `invoiceEmail` | 세금계산서 발행 메일주소 |
| `bankName` / `bankAccount` / `depositorName` | 계좌 정보 |
| `orderMethod` | 발주방식 (메일/사업자몰/개별요청/문자 등) |
| `invoiceTiming` | 증빙구분 — 계산서 발행 시점 |
| `contactName` / `contactPhone` / `contactEmail` | 담당자 |
| `note` | 메모 |
| `attachments` | 사업자등록증·통장사본 등 첨부 |
| `isActive` | |

노션에 있던 "아이디/비밀번호" 필드는 제외한다(평문 저장 금지).

| 필드 | 설명 |
|---|---|
| `id` | |
| `partnerId` | 주 거래처(생산업체) — 선택 |

| `category` | 원단/부자재/포장재/사은품 등 |

| `basePrice` | 기본단가 |

카탈로그는 처음엔 비어 있어도 되고, 발주서 저장 시 카탈로그에 없는 품목은 등록 제안으로 자연스럽게 채워진다.

### `purchaseOrders` (발주서)
| 필드 | 설명 |
|---|---|
| `id` | |
| `docNo` | 자동채번, 예: `PO-20260928-001` |
| `partnerId` | 거래처 |
| `orderDate` | 발주일 |
| `status` | 발주 / 생산중 / 입고완료 / 취소 |
| `lineItems[]` | `materialId`(선택) · 품목명 · 규격 · 수량 · 단위 · 단가 · 합계 |
| `deliveryPlace` | 납품장소 |
| `subtotal` / `vat` / `total` | |
| `note` | |

품목행은 `materialId`가 있으면 카탈로그 연동, 없으면 프리폼 텍스트만 저장한다.

## 화면 구조

`거래관리` 메뉴 하위:
- **거래처관리** — `partners` CRUD, 분류별 필터
- **원부자재관리** — `materials` CRUD (선택적 사용)
- **명세서 발행** — 발주서 작성/조회/발행

명세서 발행 화면: 상단에서 분류 선택 → 해당 분류 거래처만 드롭다운에 노출 → 품목 입력은 기존 입금요청 품목행에서 쓰는 자동완성 + 즉석등록 UI 패턴을 재사용한다.

## 문서 발행

기존 `scripts/settlement_excel.py`(openpyxl) 패턴을 재사용해 발주서 전용 엑셀 템플릿을 추가한다.

## 스코프 밖 (다음 단계)

- 판매납품처(2번): `partners`와 기존 `brands`가 개념적으로 겹친다 — 신규로 만들지 `brands`를 확장할지는 2번 착수 시 별도 결정.
- 매입공급처(3번), 펫페이스/아롬나옴/로렌츠B2B 발주서→입금요청 자동 연동.
- 완제품 `materials`/`purchaseOrders`가 NPB 정산 상품과 매칭되는 방식.
- 재고 추적, 발주 시점 자동 계산(리드타임 기반).
- PDF 발행.
