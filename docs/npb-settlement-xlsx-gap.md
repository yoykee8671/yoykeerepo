# npb 정산서 엑셀 — 실제 발행본과의 차이 정리

2026-10-08. 도톤 2026-08 정산을 이 앱으로 돌려 받은 파일
(`npb_DOTEON_202608 (3).xlsx`)이 그대로 쓸 수 없는 상태라, 손으로 고쳐서
발행했다. 무엇이 어떻게 다른지와 고칠 순서를 적어 둔다.

비교 기준은 실제로 발행해 온 문서다:
`kpi/db_202606/npb정산서/(도톤)우프_2026-5월 판매정산서.xlsx`

---

## 한 줄 요약

실제 정산서는 **수식으로 엮인 16장짜리 워크북**이고, 우리가 내보내는 것은
**값만 박힌 3장짜리 표**다. 숫자가 틀린 것을 넘어 문서의 성격이 다르다.

| | 실제 발행본 (5월) | 우리 출력 (8월) |
|---|---|---|
| 시트 수 | 16 | 3 |
| 채널별 원본(DB) 시트 | 13장 (채널마다 1장) | 없음 |
| 셀 수식 | 거의 전부 수식 | **하나도 없음** |
| 채널 표 칸 구성 | 채널마다 다름 | 전 채널 동일한 6칸 |
| 재고현황 | 품목별 기초/입고/출고/기말 + SUM | 품목명만, 숫자 전부 0 |
| DB)입출고목록 | 원장 전체 | 머리글만, 데이터 0행 |
| 할인계 | `정가계 − 매출계` | **항상 0** |

## 항목별 진단

### 1. 할인계가 늘 0 — 가장 큰 숫자 오류

실제 발행본 `종합정산`:

```
D4 = '채널별 판매데이터 정리'!K84   (정가합계)
F4 = '채널별 판매데이터 정리'!K85   (매출합계 = 할인·프로모션 반영)
E4 = D4 - F4                       ← 할인계는 이 차액이다
```

우리 출력은 `D4=990,000 / F4=990,000 / E4=0`. 채널 표에 **프로모션가·할인율
칸 자체가 없어서** 매출이 늘 정가와 같게 나오고, 그래서 할인계가 0이 된다.

5월 실제값은 할인계 524,280원이었다. 이 금액이 통째로 빠진 채 이익까지
흘러간다.

### 2. 채널별 집계 블록(K83~K87)이 비어 있음

실제 발행본은 채널 시트 아래에 다섯 줄의 집계가 있고, `종합정산`이 그
칸들을 가리킨다.

```
K83 = G8+M15+H49+...   총 판매수량
K84 = L8+L15+L49+...   정가합계
K85 = I8+I28+I49+...   매출합계
K86 = J8+J22+J49+...   공제합계
K87 = K8+K15+K49+...   정산합계
```

우리 출력에는 `J78~J82`에 **라벨만 있고 K열이 비어 있다.** 종합정산이
참조할 곳이 없으니 모든 수치를 따로 계산해 값으로 박아 넣고, 그래서 두 장의
숫자가 서로 어긋난다. (→ "정산확정과 워크시트 값이 다르다"의 원인)

### 3. 채널마다 칸 구성이 다른데 하나로 찍음

실제 발행본은 채널의 거래 형태에 따라 표가 다르다.

| 채널 | 칸 구성 | 태그 |
|---|---|---|
| 몽슈슈 | 정가 · **공급가** · 기본수수료 · 판매수량 · 프로모션차감 · … | 위탁재고 |
| 스마트스토어 | 정가 · **프로모션가** · **할인율** · 판매수량 · 매출합계 · 수수료 · … | 직매출 |
| 테일릿 | 정가 · **대리점가** · 기본수수료 · … | 매입(판매) |
| 철수마켓 | 정가 · 프로모션가 · **공급가** · 수수료율 · … | 판매자위탁배송 |

우리는 전 채널에 `상품·수량·정가·매출·공제·정산` 6칸을 똑같이 찍는다.
받는 쪽이 자기 계약 조건을 확인할 수 없다.

생성기(`scripts/npb_settlement_xlsx.py`)의 `build_channels`는 이미
`headers`/`rows`/`totalRow`/`tag`/`desc`를 받아 그리도록 **일반화되어 있다.**
못 쓰고 있는 쪽은 서버의 `npbBuildXlsxSpec`(server.js:4279)이며, 거기서
6칸으로 고정해 넘긴다. → 고칠 자리는 대부분 서버다.

### 4. 재고확정 내용이 하나도 안 실림

실제 발행본 `종합정산` 우측:

```
L9  8809879544118   M9 도톤…풋클리너   N9=O9+P9  … W9=N9+Q9-T9
L10 8809879544101   M10 도톤…스프레이  …
N12..Y12 = SUM(…)
N6/W6 = 기간,  Q6 = N6&" ~ "&W6
```

우리 출력은 품목명만 있고 **N~Y가 전부 비어 있으며 합계는 0**이다.
바코드(L열)도, 기간 머리글도 없다.

`DB)입출고목록`은 **머리글 한 줄만 있고 데이터가 0행**이다.

생성기에는 두 블록을 쓰는 코드가 다 있다(`build_summary`의 inventory,
`build_ledger`). 즉 **`spec.inventory` / `spec.ledger`가 빈 채로 넘어간다.**
재고 확정 화면에서 넣은 값이 정산서 spec까지 이어지지 않는 것이 원인.

### 5. 채널 원본(DB) 시트가 통째로 없음

실제 발행본에는 `DB)스마트스토어`, `DB)쿠팡로켓`, `DB)몽슈슈` … 13장이 있고,
채널 표가 그 칸을 직접 가리킨다(`='DB)몽슈슈'!E11`). 숫자의 출처를 받는 쪽이
따라갈 수 있다.

우리는 업로드한 원본을 `uploads[].rawRows`로 들고 있으면서도 시트로 내보내지
않는다.

### 6. 수식이 하나도 없음

실제 발행본은 합계·비율·차액이 전부 수식이다. 받는 쪽이 셀을 눌러 검산하고,
숫자 하나를 고치면 아래가 따라 움직인다. 우리 출력은 전부 상수라 고치면
합계가 깨진다. 손으로 고쳐 보낸 이번 건이 바로 그 상황.

이익분배도 실제는 `E16 = J4*D16`인데 우리는 값이다.

### 7. 판매기간 머리글에 월이 빠짐

```
실제:  판매기간 2026 5/1 - 5/31
우리:  판매기간 2026  -            ← start/end 가 빈 문자열
```

`npbBuildXlsxSpec`이 `period.start/end`를 그대로 넘기는데 그 값이 채워지지
않는다.

### 8. 상품 SKU가 한글·영문 섞여 중복

철수마켓·스파크펫 블록에 `DOTEON Foot Cleaner`(0)과
`도톤 포레스트 아웃도어 스프레이 150ml`(3)이 함께 있다.

원인은 상품 매칭 키워드가 "동의어"가 아니라 "전부 포함"으로 등록돼 있던 것.
**2026-10-08 수정·배포 완료**(PR #42). 다만 매칭은 업로드 시점에 한 번
일어나므로, **이미 올린 파일은 다시 올려야** 한 줄로 합쳐진다.

## 고칠 순서

앞의 것이 뒤의 것의 토대라 순서를 지키는 편이 낫다.

1. **채널 표를 채널별 칸 구성으로** — 프로모션가/할인율/공급가/대리점가가
   들어가야 매출이 정가와 갈라지고, 그래야 할인계가 산다.
   (`npbBuildXlsxSpec`에 채널 유형별 레이아웃 추가)
2. **집계 블록(K83~K87)과 종합정산 상호참조를 수식으로** — 두 장의 숫자가
   구조적으로 같아진다.
3. **재고·원장 spec 연결** — `settlement.inventory` / `ledger`를 채운다.
   (생성기 쪽은 손댈 것이 거의 없다)
4. **채널 원본 DB 시트 출력** — `uploads[].rawRows`를 시트로.
5. **나머지 수식화** — 이익분배, 실비, 각 합계.
6. **판매기간 머리글**.
